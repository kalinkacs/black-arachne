# Black Arachne

Black Arachne 0.2 — защитное расследование Linux-инцидентов в режиме наблюдения. Он импортирует метаданные OpenSSH и sudo из Linux journal, собирает досье по входу SSH, фиксирует прогноз Red и сравнивает три варианта решения. Интерфейс показывает прогноз, решение каждого варианта и хронологию улик.

## Быстрый запуск

Нужен Python 3.12. Сторонних пакетов и ключа API для обычного запуска не требуется.

```sh
python3 -m arachne demo
python3 -m arachne serve
```

Откройте [локальную панель](http://127.0.0.1:8765). В эпизоде `lab-unverified` проверка Red меняет преждевременное закрытие на запрос данных. В эпизоде `lab-misleading-change` обычная проверка замечает более серьёзный сигнал, который выбранная Red проверка упускает. Пять лабораторных примеров проверяют работу контура.

## Данные реального Linux-хоста

Оператор запускает команды из каталога проекта. Используйте учётную запись с разрешённым чтением соответствующих записей journal. Для удалённого тестового Linux-хоста можно сохранить такой же экспорт и передать его локальной команде `import-journal`. Для реальных событий заведите отдельное хранилище.

```sh
set -o pipefail
journalctl --since '30 minutes ago' --no-pager -o json \
  SYSLOG_IDENTIFIER=sshd SYSLOG_IDENTIFIER=sshd-session SYSLOG_IDENTIFIER=sudo |
  python3 -m arachne --db linux.sqlite3 import-journal

python3 -m arachne --db linux.sqlite3 anchors
python3 -m arachne --db linux.sqlite3 investigate HOST ANCHOR_ID
python3 -m arachne --db linux.sqlite3 serve
```

Импорт сохраняет хост, время UTC, тип, идентификатор события, имя пользователя и источник. Полное сообщение journal, аргументы команд и IP из него отбрасываются. Повторный импорт тех же строк не создаёт дубликатов. При конфликте идентификатора импорт откатывается целиком. Расследование охватывает от 10 минут до входа до 15 минут после него. Совпадение хоста, пользователя и времени связывает наблюдения для проверки, а принадлежность к одному сеансу отдельно не подтверждается.

Операторы могут добавить контекст через `import-events FILE.jsonl`. Каждая строка — JSON-объект с шестью обязательными полями `id`, `timestamp`, `host`, `kind`, `actor` и `source`. Для отдельного журнала изменений используйте виды `deployment` и `change_verified`; значение `change-management` присваивается импортером доверенного источника. Связь подтверждения с заявкой в этой версии определяется по хосту, пользователю и окну времени. Качество исходных данных зависит от импортера.

## Как устроено расследование

- **Blue** применяет зафиксированную контрольную политику к видимым событиям. Политика намеренно проста, чтобы её поведение можно было воспроизвести.
- **Red** получает представление без независимого подтверждения изменения. Он прогнозирует решение Blue и выбирает одну проверку из закрытого списка. По умолчанию прогноз детерминирован.
- **Координатор** сравнивает исходный вердикт, обычную повторную проверку и результат проверки, предложенной Red. Исходный набор наблюдений, выводы и ссылки на улики сохраняются в SQLite в виде снимка.
- **Лаборатория** подаёт инертные синтетические записи. Ожидаемая метка нужна оценщику, а агентам доступны только наблюдения.
- **Панель** слушает loopback и показывает результаты в режиме чтения. Поддерживаемая среда запуска — один локальный оператор. Для сетевого развёртывания понадобятся аутентификация, авторизация и отдельное инженерное ревью.

### Red и Blue с моделью

Задайте `OPENAI_API_KEY` через окружение и добавьте `--model gpt-5.4-mini` после `demo` или после аргументов `investigate`. На один эпизод отправляются только типы записей, относительное время и локальные псевдонимы улик. Модели возвращают структурированные гипотезы, прогноз и имя разрешённой проверки. Адрес API фиксирован. Решение о проверке и применение результата остаются в локальном коде.

## Проверка

```sh
python3 -m unittest discover -s tests -v
```

Лабораторная выборка мала, заранее известна и служит проверкой сборки. Для оценки вклада Red нужны закрытые семейства эпизодов и сравнение с обычной дополнительной проверкой при одинаковом бюджете. Режим запуска исследовательский: программа формирует защитные рекомендации. Любые операции на хостах остаются за оператором.

## Регулярный сбор и разбор

Команда `cycle` сохраняет курсор локального журнала при успешном импорте и разбирает готовые SSH-входы. Разбор начинается после полного 15-минутного окна наблюдений. Повторное выполнение не создаёт второго запланированного расследования того же входа. Ручное расследование позволяет повторно оценить эпизод.

```sh
python3 -m arachne --db linux.sqlite3 cycle
python3 -m arachne --db linux.sqlite3 serve
```

В `deploy/` лежат шаблоны службы и таймера systemd для тестового хоста. Они предполагают Python 3.12 по указанному в unit-файле пути, каталог кода `/opt/black-arachne`, отдельного системного пользователя и явно выданное право читать требуемый журнал. Планировщик запускается каждые две минуты после завершения предыдущего цикла. Для просмотра служебной базы нужен тот же локальный пользователь или отдельно разрешённый доступ. SQLite обслуживает один локальный экземпляр. Следите за доступным диском и архивируйте данные по принятой политике хранения.

Режим с моделями для обеих ролей включается опцией `--model` у `cycle`, `triage`, `investigate` и `demo`. Для службы можно настроить `ARACHNE_MODEL` и `OPENAI_API_KEY` через файл окружения, доступный администратору. Red формирует прогноз до ответа Blue. Независимый рецензент получает тот же каталог проверок. Blue повторно оценивает одинаковые результаты один раз, чтобы совпадающий выбор проверки не давал искусственной разницы между вариантами. Локальная политика отдельно требует подтверждения заявленного изменения для закрытия и сохраняет наблюдаемые признаки повышенного риска. При ошибке вызова модели команда сообщает о сбое. Уже записанные события и курсор сохраняются, следующий запуск может повторить разбор.

## Память и закрытая оценка

Оператор может сохранить сверенный исход реального расследования:

```sh
python3 -m arachne --db linux.sqlite3 confirm-outcome RUN_ID review --note 'Сверено с заявкой на изменение'
```

Следующее расследование может использовать до пяти похожих подтверждённых эпизодов с того же хоста. Модели получают только факт сравнения прежнего решения с подтверждённым исходом и название проверки. Текст заметки и идентификаторы хоста, пользователя и события остаются локально.

Для сравнения на закрытом наборе используйте `python3 -m arachne evaluate DATASET.jsonl`. Каждая строка содержит `id`, `family`, `expected`, `anchor_id` и массив `events` в формате импорта. Итог содержит точность вариантов, пропущенные и ложные эскалации, результат по семействам и случаи, где дополнительная проверка помогла только одному из вариантов. Метки и семейства доступны только оценщику. Для испытания с моделями добавьте `--model`. Чтобы измерить перенос на новые ситуации, храните некоторые семейства в закрытой выборке до финальной оценки.

## Проверка файлов по индикаторам

```sh
python3 -m arachne scan-files /path/to/test-files --indicators indicators.jsonl
```

Каждая строка списка содержит `sha256` и `label`. Используйте список из доверенного источника. Сканер открывает только обычные файлы, пропускает символические ссылки и специальные файлы, ограничивает объём чтения и сообщает о неполных или недоступных результатах. Код выхода 2 означает найденный индикатор, 1 — ошибку запуска, 0 — отсутствие совпадений в прочитанном объёме. SHA-256 даёт проверку точного совпадения с известным файлом. Для проверки открытия, чтения и совпадения используйте безопасные контрольные файлы. Операции над найденными файлами остаются у оператора.
